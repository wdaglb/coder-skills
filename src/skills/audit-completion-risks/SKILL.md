# Audit Completion Risks

## 概述

在任务完成收尾时，站在代码审查者角度反向质疑当前改动。
本技能只输出风险，不评价好坏、不总结优点、不做“代码够不够优雅”的泛泛审查。

## 使用时机

- 编码任务已经完成，准备给用户最终交付前。
- 已经有当前 diff 可读。
- 需要判断是否存在回归、边界失败、无关改动、验证不足。

不要在这些场景使用：

- 纯文档修改，除非用户明确要求审查文档风险。
- 尚未完成实现、还没有可审查 diff。
- 用户只要求解释、规划或普通问答。

## 审查流程

1. 先阅读当前 diff。
2. 按文件判断这次改动会影响哪些功能、状态、接口、数据或交互。
3. 反向审查：主动找真正可能出问题的地方。
4. 只输出风险项；若没有发现明确风险，输出“未发现明确风险”即可。
5. 风险必须按严重程度从高到低排序。
6. 每条风险必须给出文件位置；能定位到行号时给行号，不能定位时给文件路径和相关函数、组件或模块。

审查本身也要轻量：不要把收尾审查扩展成完整测试计划、回归清单或二次需求分析。只有当前 diff 中存在真实故障路径时，才提出补充验证；简单任务不要因为“没跑更多测试”被迫进入长测试阶段。

## 审查重点

优先看这些问题：

- 原有功能是否可能回归。
- 失败情况是否处理完整。
- 空数据、重复点击、网络失败是否会出问题。
- 是否改到了无关文件或超出任务范围。
- 是否缺少必要验证或测试。
- 状态是否能恢复，例如保存失败后 loading 是否结束、按钮是否恢复、错误是否可见。
- 多次触发是否会造成重复请求、重复提交、重复写入或竞态。

不要把精力放在这些内容：

- 代码是否足够优雅。
- 命名是否还能更漂亮。
- 抽象是否还能更高级。
- 没有实际故障路径的风格偏好。

## 交互审查口径

遇到按钮、表单、请求、弹窗、轮询、上传、导出等交互改动时，必须说明：

- 禁用：什么时候禁用，是否能防重复点击。
- 点击：loading 或 pending 状态什么时候开始。
- 完成：成功、失败、取消、异常时状态怎么恢复。
- 失败：网络失败、服务端错误、空响应时用户能否感知。

例如保存按钮，不要只写“保存逻辑有风险”，要说明：

- 提交失败时按钮会不会一直 loading。
- 重复点击会不会发多个请求。
- 成功和失败后状态是否都能恢复。

## 测试判断

重点是补测试，不是堆测试。

- 简单任务、轻任务、局部文档/配置/样式/文案/小范围代码调整，不把“未跑测试或 smoke”默认列为风险；这类任务只要求 lint、类型检查、格式检查、语法检查、静态审查等静态检查。
- 若当前技能列表或工具列表中存在 GitNexus 影响分析能力，且改动涉及代码/接口/配置行为，应优先使用 `$gitnexus-impact-analysis` 或对应 GitNexus 工具判断测试必要性；影响达到 MEDIUM / HIGH / CRITICAL、影响多个执行流程、命中关键路径，或 d=1 直接调用方较多时，未跑必要定向测试、最终测试或 smoke 应列为风险。
- 若 GitNexus 不可用、索引缺失或分析失败，不要假装已确认影响面；只基于当前 diff 和代码上下文判断，并明确风险来自未能确认影响面。
- 只有当改动涉及 bug 修复、接口/数据/权限/登录态/结算、复杂状态流转、真实回归路径或用户明确要求测试时，才把缺少定向测试、最终测试或 smoke 作为风险。
- 只指出最容易出问题且当前缺覆盖的位置。
- 失败情况一条没覆盖时，优先指出失败路径缺测试。
- 不要求为每个分支都补测试；只要求补能防真实回归的必要测试。
- 不把测试数量当成质量指标；若静态检查已经覆盖简单改动的真实风险，不再建议追加运行态、smoke 或手工回归。

## 输出格式

只输出下面结构，不要追加优点总结：

```text
审查风险：

高
- <文件路径>:<行号或位置>：<风险说明>
  - 影响：<可能坏掉的功能或场景>
  - 建议：<最小补救动作>

中
- <文件路径>:<行号或位置>：<风险说明>
  - 影响：<可能坏掉的功能或场景>
  - 建议：<最小补救动作>

低
- <文件路径>:<行号或位置>：<风险说明>
  - 影响：<可能坏掉的功能或场景>
  - 建议：<最小补救动作>

未发现明确风险：<仅在没有风险时输出这一句>
```

若某个严重程度没有风险，省略该分组。

## 硬约束

- 必须先读当前 diff。
- 只列风险，不总结优点。
- 不评价“写得好不好”。
- 不做泛泛风格审查。
- 不输出大段背景。
- 不把没有真实故障路径的偏好写成风险。
- 不遗漏文件位置。
- 不把验证不足写成“建议补充测试”就结束；必须说明缺的是哪条失败路径或回归路径。
