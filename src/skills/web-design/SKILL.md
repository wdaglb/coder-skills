# 网页设计

## 自适应确认

进行页面布局前，必须先确认页面是否需要自适应，不能在用户未确认目标视口时直接按固定宽度或默认响应式方案开做。

- 如果用户、设计稿、项目规范或现有页面已经明确要求响应式、自适应、移动端兼容或固定尺寸，则按已确认边界执行，不需要重复追问。
- 如果布局目标不明确，先用固定选项询问用户：`1. 需要自适应`、`2. 只做固定桌面宽度`、`3. 按现有项目规范`、`4. 用户自行填写`。
- 用户选择需要自适应时，默认覆盖桌面宽度和移动端窄屏宽度；如果页面面向平板、大屏看板或特定设备，也要同步确认对应断点。
- 用户选择固定宽度时，只按确认的目标宽度设计；不得偷偷加入会改变视觉效果的响应式重排，也不得把未覆盖移动端包装成已适配。
- 如果用户未确认且任务不能暂停询问，只能在交付中明确标注“自适应口径待确认”，不要把默认方案写成既定事实。

## 表单呈现确认

编写新增、编辑类表单页面前，必须先确认表单承载方式，不能默认把表单塞进独立页面或普通居中弹窗。

- 如果用户、设计稿、项目规范或现有同类功能已经明确使用独立页面、弹窗或抽屉，则按已确认边界执行，不需要重复追问。
- 如果承载方式不明确，先用固定选项询问用户：`1. 使用独立页面`、`2. 使用弹窗`、`3. 按现有项目规范`、`4. 用户自行填写`。
- 选择独立页面时，优先适用于字段较多、需要分组、需要复杂说明、需要完整路由状态、存在多步骤或保存后需要停留在详情上下文的表单。
- 选择弹窗时，只适用于字段较少、流程轻、提交路径短、关闭后可安全回到当前列表或详情上下文的表单。
- 如果用户选择弹窗，但字段过多、分组较多、内容会产生长滚动、校验说明较复杂，或普通弹窗会接近/超过视口高度，应改用抽屉型表单，不要继续使用普通居中弹窗硬塞内容。
- 使用抽屉型表单时，应让标题、关闭、取消、保存等关键操作稳定可见；字段内容可以在抽屉主体内滚动，但不要让提交按钮被长表单挤到不可见区域。
- 若字段数量和复杂度尚未明确，必须先确认字段范围或在交付中标注“表单承载方式待确认”，不得把默认弹窗当成已确认方案。

## 字段说明

编写表单字段时，如果字段 label 不是普通用户一眼能理解的业务词，必须使用 `extra` 或项目等价的字段说明能力补充解释，不能只留下缩写、系统字段名或内部概念让用户猜。

- 需要补充 `extra` 的字段包括：业务缩写、技术名词、配置开关、枚举口径、计费/额度/权限相关字段、会影响后续状态的字段，以及 label 与真实含义存在歧义的字段。
- `extra` 文案要说明用户填写或选择后的业务影响、取值边界、注意事项或失败后果；不要只重复 label，也不要写实现细节、接口字段名、数据库字段名或 AI 操作说明腔。
- 已经被当前产品用户普遍理解的字段，例如姓名、手机号、邮箱、标题、备注等，不需要为了形式完整强行增加 `extra`。
- 如果项目没有名为 `extra` 的表单属性，应使用项目现有等价能力，例如表单项说明、辅助文本、help text、description、hint 或 tooltip；不要为了一句说明临时造一套不一致的展示样式。
- 当字段解释文案来源不确定时，先使用短句业务语义说明，并在交付中标注“字段说明待产品确认”；不要把猜测的长解释写成确定口径。

## 真实渲染校验

布局完成后，必须使用浏览器真实渲染视角检查页面，不能只依赖代码阅读、静态截图想象或组件结构推断来判断布局正常。

- 使用实际浏览器打开目标 HTML 页面或本地预览页面，检查首屏、主要内容区、操作区、弹窗、表单、列表、卡片、页脚等关键区域是否偏离预期布局。
- 已确认需要自适应时，至少检查桌面宽度和移动端窄屏宽度；如果页面明确面向平板或有复杂响应式断点，也要覆盖对应宽度。
- 已确认只做固定宽度时，检查用户确认的目标视口，并在交付中明确未覆盖自适应校验。
- 重点检查元素是否重叠、错位、溢出、被遮挡、异常换行、间距失衡、滚动条异常、吸顶/固定定位异常，以及图片或卡片比例导致的布局塌陷。
- 如果浏览器真实渲染结果和代码预期不一致，以真实渲染结果为准，先修正布局再交付。
- 若当前环境无法打开浏览器或无法访问页面，必须在交付中明确说明未完成真实渲染校验及具体原因，不得把静态审查说成已经完成浏览器校验。

## 禁止文案

在创建或修改 HTML 页面、静态模板、Demo、管理后台原型或页面片段时，用户可见文案必须保持用户视角，不能把实现过程、AI 生成过程或开发调试信息写到页面上。

- 禁止在页面标题、正文、按钮、表单说明、占位符、空状态、Tooltip、Toast、弹窗或帮助文本中出现 AI 提示词、Prompt 片段、助手思考过程、生成说明、任务规划、验收步骤等非用户视角内容。
- 禁止把“点击某按钮后，在弹窗里输入某内容”这类 AI 操作说明腔写成页面文案；页面只表达用户当前能理解的业务动作和结果。
- 禁止把框架、组件库、接口封装、缓存、队列、构建工具、部署方式、鉴权细节、日志链路等内部技术实现写进普通用户页面；除非该页面本身就是面向开发者的产品功能。
- 页面文案应优先来自用户明确给出的产品文案、设计稿已有文案、项目现有同类页面文案或后端返回的用户可见 `message`。
- 文案来源不确定时，优先保持克制，使用短句业务语义文案；仍无法确定时不要脑补长段说明，应在交付中标注“文案待产品确认”，而不是把不确定内容写进页面。
